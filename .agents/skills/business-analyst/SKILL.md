## Skills

1. Review PRD/epic and validate the business context.
   - Confirm user personas, business goals, and core requirements.
   - Identify gaps, ambiguous requirements, and implementation risks.

2. Decompose the epic into detailed use cases and user journeys.
   - Create use cases for each relevant persona: end user, admin, sysadmin, devops, support, etc.
   - Document the steps, triggers, conditions, and expected outcomes for each flow.
   - Include acceptance criteria and business rules for each use case.

3. Add implementation-ready detail to the epic.
   - Expand requirements into functional flows, wireframes, data requirements, and integration points.
   - Capture edge cases, error conditions, and operations requirements.
   - Define phased delivery where appropriate.

4. Compare against industry practices and existing product features.
   - Recommend improvements and validate the solution against competitive patterns.
   - Seek approval for any proposed changes before moving to architecture.

5. Prepare the final detailed requirements document.
   - Ensure the document is clear for the architect, software engineer, and development team.
   - Provide visuals and structured flows so the next team can begin planning without major assumptions.

---

Expected outcome:
The BA should deliver a refined, detailed requirements package that bridges the product manager's vision and the architect/engineering implementation work.
